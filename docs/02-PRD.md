# L.Note（Inkpad）产品需求文档（PRD）

> 阶段二：PRD 撰写　|　版本：v0.20.44　|　状态：已实现（需求回溯归档）　|　更新日期：2026-08-12
> 需求描述遵循 **EARS 原则**（Ubiquitous / Event-driven / Unwanted / State-driven / Optional）撰写。

---

## 1. 背景

L.Note 起源于"一个工具覆盖本地文本处理全场景"的诉求：开发者写笔记要语法高亮、调接口要 JSON 格式化、画流程要 Mermaid、洗数据要转义与编码工具、文档一多还要组织管理。市面上要么是纯在线工具（数据隐私存疑），要么是功能单一的单点工具（来回切换低效）。

本 PRD 面向 v0.20.x 版本，对已实现的完整功能进行需求归档，明确每条需求的 EARS 表述与验收标准，作为后续迭代与回归测试的基线。

## 2. 目标

- **G1**：成为开发者日常使用的本地文本工作台，覆盖写、编、画、洗四大场景。
- **G2**：文档数据 100% 本地化，无网络请求、无账户、无数据上传。
- **G3**：文档组织高效：分组 / 收藏 / 置顶 / 批量 / 回收站，误删可恢复。
- **G4**：工程可维护：真实 ESM 模块化 + 自动化测试 + 一键打包分发。

## 4. 功能清单（EARS 原则）

### 4.1 编辑器基础（Ubiquitous）

- **FR-1**：系统应始终支持 12 种语言的语法高亮（Markdown/JSON/XML/HTML/JS/Python/CSS/SQL/Shell/YAML/C 系/Mermaid）。
- **FR-2**：系统应始终提供括号自动配对、自动补全、代码折叠、多光标、行号点击选行能力。

### 4.2 文档与预览（Event-driven / Ubiquitous）

- **FR-3**：当用户点击「👁 预览」时，系统应渲染当前 Markdown 文档的 HTML 预览（marked + highlight.js 代码高亮 + KaTeX 数学公式）。
- **FR-4**：当文档包含 Mermaid 代码块时，系统应异步渲染流程图/时序图/思维导图，并支持缩放查看。
- **FR-5**：系统应始终提供富文档（思维笔记）能力：块编辑、选中文本浮出工具条（bubble menu）、飞书式左侧大纲（TOC + 大纲搜索 + 标题跳转）。
- **FR-6**：当编辑器内容变更时，系统应在去抖窗口后自动保存并更新状态栏（保存时间 / 编辑状态）。

### 4.3 工具集（Event-driven）

- **FR-7**：当用户触发 JSON 格式化/压缩/转义/反转义/Unicode↔中文/Base64/URL 编码时，系统应替换当前选区或全文为处理结果。
- **FR-8**：当用户触发文本工具（大小写转换、全角半角、去重、缩进计算、行排序）时，系统应作用于当前选区。
- **FR-9**：当用户打开文件比较窗口时，系统应展示双栏行级 diff，并支持加载本地文件参与比较。
- **FR-10**：系统应提供编码转换、时间戳（北京时间）、代码段插入、剪贴板历史、图片查看器（缩放/平移/适应窗口）。

### 4.4 查找与替换（Event-driven / State-driven）

- **FR-11**：当用户打开查找/替换浮层时，系统应显示输入框、上一个/下一个导航、收藏规则与更多工具。
- **FR-12**：当用户在输入框键入并触发（Enter / 按钮）时，系统应高亮所有匹配项，并以醒目样式标识当前匹配并滚动至可见区域。
- **FR-13**：当用户启用正则模式时，系统应按照正则表达式匹配；替换支持批量替换全部匹配。
- **FR-14**：当用户收藏某条查找规则时，系统应将其持久化到本地存储，供历史下拉复用。
- **FR-15**：当用户拖动浮层标题栏时，系统应移动浮层并记忆其位置（重启后保持）。
- **FR-16**：查找浮层状态（规则/位置）应始终在输入框失焦与重新打开间保持。

### 4.5 侧栏与文档组织（State-driven / Event-driven）

- **FR-17**：系统应始终提供飞书风格侧栏导航：最近 / 我的空间 / 知识库 / 收藏 / 回收站 五个视图。
- **FR-18**：当用户点击「最近」时，系统应展示全部未删除文档，按 置顶 > 今天 > 昨天 > 本周 > 更早 分组排序。
- **FR-19**：当用户点击「知识库」时，系统应仅展示 Markdown 与富文档类文档。
- **FR-20**：当用户点击「收藏」时，系统应仅展示已收藏文档（favorite=true）。
- **FR-21**：当用户点击「回收站」时，系统应展示已软删除文档，每条提供「恢复」与「彻底删除」操作。
- **FR-22**：当用户通过三点菜单或批量栏删除文档时，系统应执行软删除（标记 deleted/deletedAt），文档移入回收站而非立即销毁。
- **FR-23**：当用户在回收站点击「恢复」时，系统应清除 deleted/deletedAt 标记，文档回到原视图。
- **FR-24**：当用户在回收站点击「彻底删除」时，系统应永久移除文档记录并清理其本地正文存储。
- **FR-25**：当用户进入批量管理模式时，系统应展示全选、已选计数、批量导出、批量删除（红色）、退出等操作。

### 4.6 数据与存储（Ubiquitous / Unwanted）

- **FR-26**：系统应始终将文档索引保存于 localStorage（`inkpad.docs.v1`），正文按文档单独存储（`inkpad.content.<id>`），避免大内容导致列表丢失。
- **FR-27**：当单个文档正文超出本地存储上限时，系统应保留列表记录，正文不写入（内容改由磁盘文件兜底），其余文档不受影响。
- **FR-28**：当应用启动时检测到当前活动文档已被删除时，系统应自动切换到第一篇未删除文档。

### 4.7 桌面集成（Optional）

- **WHERE** 使用桌面版（pywebview），系统应提供本地磁盘文件打开/保存/导入能力（原生文件对话框）。
- **WHERE** 构建 Windows 分发版，系统应支持 PyInstaller 单文件打包（`L.Note.exe`），且以 `file://` 直载即可运行。

## 5. 流程说明

### 5.1 主流程：新建 → 编辑 → 保存 → 组织

```
新建文档(FAB) → 选择类型(文本/Markdown/JSON/图表/富文档)
  → 编辑(语法高亮/工具/预览/查找替换)
  → 自动保存(localStorage，去抖)
  → 侧栏组织(收藏/置顶/分组/批量)
  → 删除(软删除 → 回收站) → 恢复 或 彻底删除
```

### 5.2 软删除与回收站数据流

```
删除(单删/批量) → 标记 deleted=true, deletedAt=now
  → persist() 持久化 deleted/deletedAt 字段
  → 视图刷新（当前视图移除该文档；若删除的是当前文档则切换 activeId）
  → 回收站视图展示「删除于 <时间>」+ 恢复/彻底删除
```

### 5.3 查找替换流程

```
打开浮层 → 输入关键词(手动触发，非自动) → 高亮全部匹配 + 当前匹配定位
  → 上一个/下一个导航（双向迭代匹配，光标同步移动）
  → 替换单个/全部/批量弹窗 → 收藏规则供历史复用 → 拖动浮层记忆位置
```

## 7. 数据指标（本地应用，无埋点，采用本地可观测口径）

| 指标 | 口径 | 数据来源 |
|---|---|---|
| 文档总数 | 未删除文档数量 | localStorage `inkpad.docs.v1` |
| 活跃度 | 文档 updated 时间分布（今天/昨天/本周/更早） | 文档索引 |
| 收藏/置顶率 | favorite=true / pinned=true 占比 | 文档索引 |
| 回收站规模 | deleted=true 文档数量 | 文档索引 |
| 稳定性 | 测试通过率（单测 24 + E2E 23） | `reports/test-report.json` |
| 性能 | 查找高亮扫描耗时、预览渲染 debounce | 控制台性能观测（开发态） |

> 说明：由于产品定位纯本地、无账号，**不采集任何远程埋点**；上述指标全部可离线计算，仅作开发与自评口径。若后续引入云同步/多端，需补充埋点方案评审。

## 8. 边界场景与异常状态

| 场景 | 系统行为 |
|---|---|
| 单文档正文超 localStorage 上限 | 索引照常保存，正文跳过，列表不受影响（FR-27） |
| 当前活动文档被删除 | 自动切到第一篇未删除文档（FR-28） |
| 回收站为空 | 显示「回收站为空」空态提示 |
| 收藏/知识库为空 | 显示对应空态文案（如「暂无收藏文档，右键文档可收藏」） |
| 查找无匹配 | 保留上次查询缓存，避免重复全量扫描（性能优化） |
| 批量删除含当前活动文档 | 软删除后自动切换 activeId 至未删除文档 |
| 文档重名 / 空名 | 重命名空名拒绝保存并提示「文档名不能为空」 |
| 磁盘文件删除 | 仅移除本地记录，不删除磁盘源文件（提示文案明示） |

## 9. 权限与数据口径

- **无账户、无权限体系**：单机单用户，所有文档对本机用户可见。
- **数据存储口径**：索引（不含正文）存 `inkpad.docs.v1`；正文逐文档存 `inkpad.content.<id>`；活动文档存 `inkpad.active.v1`；查找收藏规则存于查找模块私有状态。
- **删除口径**：普通删除 = 软删除（进回收站）；回收站「删除」= 彻底删除（不可恢复，清理正文存储）。
- **磁盘文件口径**：关联磁盘文件的文档删除/软删除不触碰源文件。

## 10. 验收标准（DoD 摘要）

| 需求 | 验收标准 |
|---|---|
| FR-3 Markdown 预览 | 打开预览后渲染 HTML；代码块高亮；`$...$` 数学公式渲染为 KaTeX |
| FR-11~16 查找替换 | 打开/关闭正常；手动触发查找；匹配高亮 + 当前匹配醒目定位；上/下导航光标同步；弹窗可拖拽且位置记忆 |
| FR-17~21 侧栏视图 | 五个导航项点击均能切换并正确过滤列表；回收站展示删除时间与恢复/彻底删除按钮 |
| FR-22~24 软删除 | 删除后列表移除且回收站出现该文档；恢复后回到原视图；彻底删除后记录与正文均消失 |
| FR-25 批量管理 | 进入批量模式出现蓝色工具条；多选/全选计数正确；批量导出逐个下载；批量删除进回收站 |
| FR-26~28 存储 | 重启后数据完整；activeId 不指向已删除文档；超限文档不影响列表 |
| G2 本地化 | 全程无网络请求（测试断言无 console 错误与外部请求） |
