## 4. 未覆盖的 P0

### 4.1 AI 图表生成（M3，GEN-1~GEN-6，PRD 功能 #9~#12）

PRD §5.3 的完整链路——选中文本或输入描述 → 生成结构 JSON → schema 校验与重试 → 本地布局器算坐标 → 预览浮层确认 → 新建 flow / mind 文档——在 9 屏中没有对应页面。这是 v0.22.0 的两个 P0 方向之一，也是本模块相对 Notion AI、Obsidian 插件的差异点（16 文档 §5「生成即本地文档可编辑」）。缺失的屏至少包括：生成入口与描述输入、生成处理中态、结构预览浮层、校验失败重试提示。

### 4.2 未配置引导（CFG-5，PRD 功能 #8）

PRD 要求「未配置或 Key 无效时，调用助手 / 生成前弹出引导进入设置，功能按钮置灰并提示」。设计稿只给了配置完成后的正状态（p6 / p7 / p8），没有空白引导态，也没有按钮置灰态，首次使用者的首屏路径缺失。

### 4.3 助手状态与异常态

PRD §7 列出的边界场景在设计中无对应表现：超长选区截断提示、401 / 鉴权失败、流中断保留已接收内容、生成中切换文档或关闭面板、单任务并发（新任务先停旧任务）。p1 只有入口工具条，没有流式输出中的结果面板与停止按钮。

## 5. 超出本期范围的设计

### 5.1 知识库问答（p4 / p9）

知识库列表、索引状态、推荐提问、最近问答、引用检索与知识库级模型配置，构成一条完整的 RAG 链路，需要文档切片、向量化与检索能力；p7 的「嵌入模型」类型与 p4 / p9 的 `bge-small-zh` 都指向本地向量化。这与 16 文档 §4「不引入第三方 Python 依赖（沿用标准库 urllib + 既有 worker 线程）」存在实现冲突，且知识库本身在需求池之外。

### 5.2 整篇智能摘要（p3）

全文摘要 / 章节摘要 / 关键词提取 / 大纲结构 / 问答对生成五种产出。PRD 的助手能力以选中文本 4000 字符为上限（§6），整篇摘要需要分片与汇总策略，属于新的处理链路。

### 5.3 AI 命令面板（p5）

全局命令面板把 AI 能力聚合成统一入口，其分类体系、快捷键与命令集都超出 PRD 范围，且需要与既有全局「搜索文档」快捷键协调。

### 5.4 模型库与场景模型分配（p6 / p8）

PRD 的配置模型是单套 `{ baseUrl, apiKey, model, temperature, timeoutSec, maxTokens }`。设计改为「模型库 + 多模型 + 场景绑定 + 每模型适用场景开关 + 对话 / 嵌入双类型」，属于数据模型层级的重构。

## 7. 结论与版本切分建议

### 7.1 可直接纳入 v0.22.0

- p6 / p7 / p8 的模型配置，对应 CFG-1 / CFG-2 / CFG-4 / CFG-6，裁剪为单模型配置即可落地
- p1 的选中文本助手入口，对应 AST-1

### 7.2 需补齐 v0.22.0 缺口

- 新增图表生成全链路屏（M3，GEN-1~GEN-6）
- 新增未配置引导空白态（CFG-5）
- 补充助手指令集、结果面板、停止与结果处置（AST-2~AST-5）及 §7 异常态

### 7.3 建议后置到 v0.23+

- 模型库与场景模型分配（p6 / p8 的重构部分）
- 知识库问答（p4 / p9）
- 整篇智能摘要（p3）
- AI 命令面板（p5）

### 7.4 需要统一的口径

- 指令集：PRD 六条（润色 / 续写 / 总结要点 / 扩写 / 纠错 / 生成大纲）与设计中三处命令名对齐为一份字典
- 配置数据模型：单模型配置与模型库二选一，作为 v0.22.0 实现基线

### 7.5 设计需补充的屏

未配置引导态、图表生成入口与描述输入、生成处理中态、结构预览浮层、校验失败重试态、删除模型引用拦截、场景绑定与「适用场景」的优先级说明。
