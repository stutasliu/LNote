# L.Note AI 模块需求规划

> 阶段一：需求规划　|　目标版本：v0.22.0　|　状态：研发完成，测试验收中　|　更新日期：2026-09-11

---

## 1. 产品背景

L.Note 是纯本地、无账号的桌面文档编辑器，已具备文本文档、富文档（块编辑器）、流程图（flow）、思维导图（mind）、便签等能力。用户希望在不破坏「本地优先、数据自主」定位的前提下，获得 AI 辅助能力，典型诉求包括：写作润色、续写、内容总结、把一段文字直接变成流程图 / 思维导图。

与「登录即用云端 AI」的主流方案不同，本模块选择 **BYOK（Bring Your Own Key，自带 Key）接入 OpenAI 兼容接口**：

- 用户自备任意 OpenAI 兼容服务的 Base URL + API Key + 模型名，覆盖 DeepSeek、通义、Kimi、智谱、OpenAI、Ollama（本地）等；
- 请求**直连用户配置的服务商**，L.Note 不做云端中转、不建账号、不采集内容；
- API Key 保存在 **Python 侧配置文件**（`%LOCALAPPDATA%\L.Note\ai-config.json`），不进 localStorage、不回传明文，窗口仅持有掩码/占位信息。

首期功能圈定两个 P0 方向：**AI 设置 + 选中即用助手**、**AI 生成流程图 / 思维导图**。图表生成遵循既有架构约束：**AI 只产生「结构 JSON」，坐标由本地布局器计算**，生成结果直接落入现有 flow / mind 数据模型，可继续在画布内编辑。

> 关联上下文：自动更新安装竞态修复（commit 90e0c01）已提交但尚未发布，预期随 v0.22.0 一并携带发布。

## 2. 目标用户与使用场景

| 场景 | 用户行为 | 需要的 AI 能力 |
|---|---|---|
| 写作润色 | 写了一段落，觉得表达不够好 | 选中文本 → 润色 / 扩写 / 纠错 |
| 长文阅读 | 文档太长，想快速抓重点 | 选中文本 → 总结要点 |
| 内容续写 | 写不下去，想延续思路 | 选中文本 → 续写 |
| 流程梳理 | 头脑里有一串步骤，想画成流程图 | 输入描述/选中文本 → 生成流程图结构 |
| 大纲整理 | 一堆零散要点想组织成思维导图 | 输入大纲/选中文本 → 生成思维导图结构 |
| 隐私要求 | 不愿把内容交给云端厂商，有本地模型 | 配置 Ollama 本地端点，离线使用 |

## 3. 需求池与优先级

> 优先级：P0 必备 / P1 重要 / P2 增强。状态：⬜ 待开发。
> 全部 AI 配置存于 Python 侧 `ai-config.json`；不引入账号与云端中转。

### 3.1 BYOK 接入与 AI 设置（CFG）

| # | 需求 | 优先级 | 说明 |
|---|---|---|---|
| CFG-1 | 服务商预设 | P0 | 内置 DeepSeek / 通义 / Kimi / 智谱 / OpenAI / Ollama 常用 Base URL 与默认模型名，一键填入 |
| CFG-2 | 自定义 Base URL 与模型 | P0 | 手动填写 OpenAI 兼容端点、API Key、模型名；任意兼容服务均可接入 |
| CFG-3 | API Key 本地安全存储 | P0 | Key 仅存 Python 侧 `ai-config.json`（`%LOCALAPPDATA%\L.Note`），不入 localStorage，不回传明文 |
| CFG-4 | 连接测试 | P0 | 设置面板「测试连接」，校验 Base URL / Key / 模型可用 |
| CFG-5 | 未配置引导 | P0 | 首次调用 AI 前检测未配置/无效配置，弹设置引导 |
| CFG-6 | 高级参数 | P1 | 温度、单次请求超时、最大输出长度等可调 |

### 3.2 选中即用助手（AST）

| # | 需求 | 优先级 | 说明 |
|---|---|---|---|
| AST-1 | 选中文本助手入口 | P0 | 富文档 / 文本文档选中文字后，浮动工具条或右键菜单出现「AI 助手」入口 |
| AST-2 | 标准指令集 | P0 | 润色 / 续写 / 总结要点 / 扩写 / 纠错 / 生成大纲 |
| AST-3 | 流式输出 | P0 | 回复 SSE 流式逐段展示，非一次性等待 |
| AST-4 | 结果处置 | P0 | 结果可替换选中区 / 插入到光标处 / 复制到剪贴板 |
| AST-5 | 停止生成 | P0 | 生成过程中可随时停止 |
| AST-6 | 自定义指令 | P1 | 用户保存自定义 prompt 模板进指令菜单 |

### 3.3 AI 图表生成（GEN）

| # | 需求 | 优先级 | 说明 |
|---|---|---|---|
| GEN-1 | 文本 → 流程图 | P0 | 输入描述或选中文本，产出流程图结构 JSON（nodes/edges，含类型 start/end/process/decision） |
| GEN-2 | 文本 → 思维导图 | P0 | 输入描述或选中文本，产出思维导图树 JSON（root-children） |
| GEN-3 | 生成结果预览与插入 | P0 | 弹层预览结构清单，确认后创建为新 flow/mind 文档（或按上下文追加） |
| GEN-4 | 结构校验与重试 | P0 | AI 输出做 schema 校验，不合法自动重试一次或附错误回灌修正 |
| GEN-5 | 坐标本地布局 | P0 | 坐标由本地纯函数布局器计算，AI 不负责坐标，杜绝布局不稳定 |
| GEN-6 | 画布内继续编辑 | P0 | 生成结果进入现有 flow/mind 编辑器，可继续增删改 |
| GEN-7 | 基于现有图扩展/重构 | P1 | 对已有图内容请求「扩充分支 / 重新梳理」 |
| GEN-8 | 图结构可复制复用 | P1 | 生成的结构 JSON 可复制到剪贴板，便于外部再利用 |

## 4. 边界范围

- **不做** L.Note 云端 AI 服务、账号体系、内容采集与中转计费：请求只发往用户配置的 Base URL。
- **不做** 免费额度 / 试用 Key：BYOK，Key 完全由用户提供。
- 图表生成首版以 **flow（流程图）与 mind（思维导图）两种 kind** 为目标；便签、富文档等其他 kind 不做 AI 生成。
- 助手首版支持 **文本 / 富文档**两类编辑器的选中文本；PDF/图片/flow/mind 画布不提供选中即用助手（画布文字是节点内容，语义不同）。
- AI 配置不回传明文 Key；调试日志不得记录 Key 与请求体明文（仅记录耗时、状态码等）。
- 不引入第三方 Python 依赖（如 openai SDK、requests）：沿用标准库 urllib + 既有 worker 线程 + evaluate_js 回调通道。

## 5. 竞品参照

| 产品 | 可借鉴 | L.Note 的差异化 |
|---|---|---|
| Notion AI | 选中文本唤起助手、指令菜单、流式回填 | 订阅制云端服务；L.Note 为 BYOK 零订阅 |
| Obsidian + Copilot/Text Generator 类插件 | BYOK、本地优先、OpenAI 兼容 | 插件生态复杂、图表生成弱；L.Note 一体化 + 原生 flow/mind 落图 |
| ProcessOn / Xmind AI / boardmix 等 | 一句话生成流程图/导图 | 云端账号、导出受限；L.Note 生成即本地文档可编辑、可持久化 |
| DeepSeek / Kimi 网页端 | 对话能力强 | 无法直接作用选区并把结果落成应用内图表文档 |

结论：本模块取「本地优先 + BYOK + 生成物直接进入本地文档模型」的组合，把 AI 当作纯本地应用的「可选外脑」，不引入账号与云端依赖。

## 6. 待确认问题

| # | 问题 | 影响 | 建议决策 |
|---|---|---|---|
| 1 | API Key 是否需要加密存储 | CFG-3 安全性 | [Assumption] 首版以 JSON 明文存用户数据目录（随系统用户隔离），不回传明文；加密留后续增强 |
| 2 | 助手回复是否按 Markdown 渲染 | AST-3 展示与回填格式 | [Assumption] 回复按纯文本段落流式展示；回填时插入为纯文本（富文档按段落插入） |
| 3 | 生成图表触发是否同时支持「选中文本」与「纯描述输入」 | GEN-1/2 入口 | [Assumption] 两者都支持：选中文本优先作为上下文，未选中则弹输入框填描述 |
| 4 | Ollama 模型列表是否自动拉取 | CFG-1 配置体验 | [Assumption] 首版手动填模型名，不做 /api/tags 探测 |
| 5 | 是否限制并发 | AST/GEN 稳定性 | [Assumption] 同一时刻仅允许 1 个 AI 任务；新任务触发前先停止旧任务 |
| 6 | 图表生成产物默认落在哪 | GEN-3 数据流 | [Assumption] 预览确认后新建为独立 flow/mind 文档，并加入「最近」列表 |
| 7 | 失败重试策略 | GEN-4/CFG-4 | [Assumption] schema 校验失败自动重试 1 次并回灌错误；网络/鉴权错误不自动重试，展示可读错误 |
| 8 | 目标版本承载 | 发布范围 | [Assumption] v0.22.0 一并携带自动更新竞态修复（commit 90e0c01）后发布 |
