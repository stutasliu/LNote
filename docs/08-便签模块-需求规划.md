# L.Note 便签模块需求规划

> 阶段一：需求规划　|　目标版本：v0.21.0　|　状态：需求池评审中　|　更新日期：2026-08-12

---

## 1. 产品背景

参考产品「好用便签」（https://www.haoyong333.cn/）是一套桌面便签工具，核心能力包括：桌面便利贴、待办事项、提醒、时间轴、便签集组合、多彩皮肤、云同步。其受欢迎的原因在于「随手记、易用、不打扰」。

L.Note 当前是纯本地的文档编辑器，文档组织能力已有：最近 / 我的空间 / 知识库 / 收藏 / 回收站 五个视图、收藏与置顶、批量管理、软删除。用户希望借鉴「好用便签」的组织理念，为 L.Note 增加一套「完整便签模块」，把「打标签管理内容」和「轻量随手记」的能力补上。

本模块的目标不是复刻一个桌面便签，而是把便签产品的三种核心组织形态——**标签**、**便利贴**、**便签集**——融入 L.Note 现有的文档体系，延续纯本地、无广告、即开即用的定位。

## 2. 目标用户与使用场景

| 场景 | 用户行为 | 需要的便签能力 |
|---|---|---|
| 知识分类 | 文档越来越多，靠记忆找文档困难 | 给文档打标签，按标签浏览 |
| 临时记录 | 开会随手记、复制一段临时文本，不想建正式文档 | 便利贴：轻量、随时写随时丢 |
| 项目整理 | 一个项目下有多篇文档（需求、设计、测试） | 便签集：把同类文档组合成集合 |
| 快速检索 | 记得标签名，不记得文档名 | 标签视图 + 标签搜索 |

## 3. 需求池与优先级

> 优先级：P0 必备 / P1 重要 / P2 增强。状态：⬜ 待开发。
> 全部数据仍保存在 localStorage，不引入网络与账号。

### 3.1 标签系统（Tag）

| # | 需求 | 优先级 | 说明 |
|---|---|---|---|
| T-1 | 文档添加/编辑/移除标签 | P0 | 每个文档可挂多个标签；入口：右键菜单、三点菜单、编辑页内标签区 |

| T-5 | 标签管理（重命名/删除/合并） | P1 | 统一重命名全局生效；删除标签解除所有文档关联；空标签自动消失 |

### 3.4 定时提醒（Timer，v0.21.1 新增）

| # | 需求 | 优先级 | 说明 |
|---|---|---|---|

## 4. 边界范围

- **不做**云同步、账号、多端（与 L.Note 纯本地定位一致）。
- **不做**待办事项勾选、时间轴（那是独立产品，超出便签组织模块范围，列为 P3 规划）。
- 定时提醒为**应用内**提醒弹窗（无系统级通知），纯本地判断，不依赖后台服务。
- 便利贴是应用内轻量便签（嵌入侧栏/独立面板），不是系统级桌面悬浮便签。
- 便签集不创建新的目录/文件夹，只是文档的「虚拟分组」引用，删除集合不影响文档本身。

## 5. 竞品参照

| 产品 | 可借鉴 | L.Note 的差异化 |
|---|---|---|
| 好用便签 | 便签集组合、多色皮肤、随手记 | 不复制完整产品，只取标签/集合/轻量便签的组织形态，融入既有文档体系 |
| Obsidian | 标签系统（#tag、标签面板、嵌套标签） | 标签以「视图」承载，非 Markdown 语法侵入 |
| Notion | 集合/数据库视图 | 简化为一层便签集，不引入数据库复杂度 |

结论：本模块选取三者中「轻量」的部分——标签做纯元数据、便签集做虚拟分组、便利贴做独立轻量内容，全部本地存储，与现有架构一致。

## 6. 待确认问题

| # | 问题 | 影响 | 建议决策 |
|---|---|---|---|
| 1 | 便利贴是否需要多行/富文本，还是纯文本即可 | S-2 交互复杂度 | [Assumption] 纯文本 + 标题，支持换行 |
| 2 | 标签是否支持层级（如 a/b/c） | T-2 视图复杂度 | [Assumption] 首版不支持层级，平铺标签 |
| 3 | 便签集内文档是否仍保留在「最近」等原视图 | C-3 数据模型 | [Assumption] 是，便签集只是视图过滤，不改归属 |
| 4 | 便利贴是否也支持标签 | 模块边界 | [Assumption] 支持，统一标签体系 |
